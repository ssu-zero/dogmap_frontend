# 인증과 약관

`/login → /terms → /onboarding/1 → /onboarding/2 → /`

약관은 전체 동의와 필수 동의를 지원한다. 제목·안내 영역은 상단에 유지하고,
`모두 동의하기 → 필수 약관 3종 → 확인`은 한 개의 하단 액션 영역으로 화면 하단에
고정한다. 따라서 충분한 화면 높이에서는 CTA와 동의 항목이 함께 하단에 붙고, 짧은
화면에서는 해당 블록이 잘리지 않도록 페이지 전체가 자연스럽게 세로 스크롤된다. 완료
전에는 `확인`을 비활성화한다. `/terms/[slug]`는 온보딩·마이페이지에서 공통으로
진입하며 뒤로가기로 이전 문맥을 유지한다.

## 하단 CTA 배치 규칙

- 로그인과 약관의 주요 CTA는 화면 하단에서 `24px` 위에 둔다.
- 충분한 화면 높이에서는 flex 문서 흐름의 `margin-top: auto`로 하단에 배치한다.
- 앱 프레임만 뷰포트 높이를 소유한다. 내부 화면이 뷰포트 높이를 다시 선언해 프레임보다
  커지는 것을 금지한다. 짧은 화면에서 필요한 스크롤은 앱 프레임 내부에서 처리한다.

## Figma Safe Area 기준

- Figma 모바일 시안의 상단 `62px`은 iOS 상태 영역을 위한 Safe Area 기준값이다. 웹에서
  상태바를 별도로 그리지 않고, 화면 헤더와 첫 콘텐츠는 `--figma-safe-area-top` 아래에서
  시작한다.
- 약관 동의·상세와 온보딩 화면 모두 이 기준으로 헤더를 배치한다. 헤더의 좌우 여백은
  `16px`, 본문 제목과 입력·동의·상세 영역의 좌우 여백은 `20px`을 유지한다.
- 브라우저의 실제 Safe Area나 하단 브라우저 UI를 화면 요소로 복제하지 않는다. 하단 CTA는
  기존 문서 흐름과 하단 여백 규칙을 유지한다.

## 반려견 소개 온보딩

- `/onboarding/1`은 사진 선택 전·후, 이름 미입력·입력 상태를 한 화면에서 전환한다. 사진은
  선택 즉시 원형 미리보기로 바뀌고, `+` 아이콘은 사진의 오른쪽 아래에 유지한다.
- 이름 입력칸은 기본 상태에서는 배경만 보이고, 포커스 중에는 `gray-150` 1px 테두리와
  `gray-800` 입력 텍스트를 표시한다. 실제 브라우저 커서를 사용하며 Figma의 키보드는
  별도 UI로 복제하지 않는다.
- `/onboarding/2`는 크기 배지와 출생 연도를 모두 선택해야 완료 CTA가 활성화된다. 선택된
  크기 배지는 진한 테두리로, 나머지 배지는 낮은 강조도로 표시하되 다른 크기로 다시 선택할
  수 있어야 한다.
